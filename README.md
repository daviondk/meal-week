# MealWeek — рацион на неделю

**Учебный проект по ML System Design · ДЗ №1 · локальная подготовка.**

MealWeek — приложение для iOS и Android, которое помогает людям, следящим
за питанием, экономить время на недельном меню и покупках. Пользователь
сам задаёт целевые калории и БЖУ; агент уточняет предпочтения, подбирает
блюда и принимает изменения в диалоге.

**В репозитории — дизайн и инструменты разработки, не работающее приложение.**
Клиент, backend, каталог и эксперименты ещё не реализованы. Целевые метрики —
гипотезы, не достигнутые результаты.

## Какой продукт проектируем

1. Агент выясняет цели, ограничения и условия готовки, затем предлагает меню
   на семь дней **из заранее подготовленного каталога**, не генерируя рецепты.
2. На экране недели пользователь видит план и открывает карточки рецептов.
   Можно заменить блюдо, убрать или заменить ингредиент, изменить
   пропорции или число порций. Система допускает только проверенные изменения;
   неподдерживаемые варианты не выдумывает. Изменения сохраняются после подтверждения.
3. Отдельный программный калькулятор пересчитывает КБЖУ и список продуктов
   после изменений — арифметика не поручается LLM.
4. При подборе учитываются предпочтения и подтверждённая история питания.
   Запланированное блюдо не считается съеденным автоматически.

Качество **подобранного меню** планируется оценивать через **LLM-as-a-Judge**:
соответствие предпочтениям, разнообразие, учёт истории, практичность и
выполнение корректировок. Оценки судьи сверяются с человеческими;
КБЖУ, строгие ограничения и покупки проверяются программно.

Это **не медицинский сервис**: он не назначает нормы питания и лечебные диеты
и не гарантирует безопасность при пищевой аллергии.

Планируются кроссплатформенный клиент, Python-backend с LLM-агентом,
каталог рецептов и хранилище профиля, меню и истории. Реализация — в следующих ДЗ.

## Локальная подготовка

Нужны **Python 3.12**, **Git**, **uv** (проверено с 0.10.9).
Ruff 0.15.1, pre-commit 4.5.1 и их зависимости зафиксированы в `uv.lock`.
Из корня репозитория:

```bash
uv sync --locked --group dev
uv run --locked pre-commit install
uv run --locked pre-commit validate-config
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked python -m unittest discover -s tests -v
uv run --locked python scripts/check_repo.py
uv run --locked pre-commit run --all-files
```

Ruff отвечает за линтинг и форматирование Python. Локальные pre-commit-хуки
запускают его, тесты и проверку документации. Новые файлы нужно добавить
в Git-индекс; изменения форматера — проверить и добавить заново.

Первый `uv sync` может скачать пакеты; без сети нужны заполненный кэш и
`--offline`. Хуки `repo: local` не клонируют чужие репозитории. Команды
не отправляют документы в LLM API и ничего не публикуют.
